# 最终交付前强制检查

两条路径均执行，A、B分别检查；先检查并修正，后展示。不得先展示有误图片再声明通过。

## 1. IP身份与比例

将最终图与用户IP原图逐一对照，不能只对照图库参考或中间图：头部轮廓及两侧起伏、宽高比例、头身比例、五官大小和间距、眼神特征、腮红、嘴型、肤色及四肢比例。确认是用户提供的IP，不是原图库角色，也不是同类型新角色。服饰动作变化不能造成头部变形或角色比例变化。

原IP带帽子必须保留，允许贴合KV氛围微调颜色形态；原IP无帽子不得新增。不要因为新年风格自动去帽或加帽。

## 2. 文案

逐字核对主标题与用户输入完全一致，检查错别字、缺字、多字、重复、错序。副标题提供时同样逐字核对；未提供不得自行补写。额外展示文字按用户原文检查，清除原图库标题、日期和无关文字。检查字体设计贴近图库参考、二维平面表现和文字完整可读。

检查主副标题整体文字组是否在全画布垂直方向居中，组中心应对齐画布高度50%；只在局部区域居中或主标题居中而整个文字组偏上均不通过。

## 3. 严格尺寸

读取最终文件真实宽高或平台可靠图片元数据，必须满足 `width * 9 == height * 16`；例如2048×1152、1920×1080、1600×900。1672×941不合格，不能描述为已达到16:9。

PNG可离线校验：

```bash
python3 scripts/check_size.py /absolute/path/final-a.png /absolute/path/final-b.png
```

脚本只检查尺寸，不检查IP或文字；这些必须读图完成。非PNG可使用平台元数据或适用的本地图片读取工具，不凭提示词或预览估计尺寸。

不合格时优先以明确尺寸重新生成/扩展画布；如做裁切只允许不损伤文字和IP且不变形的裁切，必须通过适用图片编辑工具完成，再做整套终检。不允许非等比缩放，不允许以“接近16:9”通过。

## 4. 验收记录与修正

内部逐图记录：IP身份及比例、帽子状态、主标题、副标题、额外文字、字体、真实宽高和比例检查结果。无法确认的项目记为未确认，不能写通过。

发现错误只修正对应分支一次，再次执行全部检查；仍失败则说明具体问题并保留任务，不宣称全部完成，也不将失败图或无标题图凑成两张成品。正常成功时只展示两张最终带文案图片；无标题图和被淘汰图均不外显。


## 5. 展示与提交清单

内部验图使用不会向用户发出图片预览的读取方式。参考KV、分析稿、中间图、返修图及淘汰版本均不预览、不附链接、不进入提交清单。

只有A、B的全部验收项目通过，才创建内部提交清单，且仅包含两个最终成品文件。交付前确认：清单恰好两张、两张都通过、两张都未提前展示。任一未通过时仅报告文字状态，暂存所有图片，不进行部分图片交付。

两张在同一次最终交付中统一展示，各一次。选择平台原生最终图片展示或回复图片嵌入中的一种，防止工具展示后又用Markdown重复展示。交付目录和附件不得混入参考图、过程图、返修图或分析记录。
