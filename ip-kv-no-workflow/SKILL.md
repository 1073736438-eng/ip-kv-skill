# IP KV生成-无workflow

一句话生成带IP的运营KV：上传IP图并提供主标题；副标题和其他要求可选。无需Mixgo，不要求配置Mixgo密钥。此skill是平台原生能力的编排说明，不是Mixgo API脚本。

## 首次使用问候

用户安装后首次打开或调用本skill、尚未提交生成需求时，发送：

> 你好！上传一张IP图片，用一句话描述你想要的KV，并写上主标题，就能生成两版设计。副标题和其他要求可选填。

skill本身没有安装完成事件钩子；这句问候在首次交互时发送，不承诺安装瞬间自动弹出。若用户已提供完整需求，直接开始生成，不重复问候或要求重新填写；缺少必填项时仅提示补充缺项。

## 全程强制规则

1. 字体设计严格参考本次选中的图库参考图：保留其字形类别、粗细、笔画特征、倾斜角度、字距、行距、标题层级、排列节奏、描边与平面色彩处理。仅根据用户文字长度作必要适配，不自行换成通用可爱字或另一种字体风格。继续遵守二维平面文字约束，不复制参考图可能存在的三维挤出。
2. IP比例与脑袋严格锁定用户输入IP图：头身比、头部宽高比、整体轮廓、左右起伏、眼睛大小与间距、五官相对位置、腮红形状、躯干及四肢粗细长度比例必须保持一致。只允许整体等比缩放以适配画面，不拉伸、不压扁、不圆化、不改头型、不改变头身比例。动作和服饰可调整，但不得因此改变角色原始比例和脑袋结构；头型及比例保真优先于姿态、视角变化和参考图角色占比。
3. 参考KV、分析稿、无标题中间图、返修图、被淘汰图只供内部读取、保存与传递；不在用户回复、进度消息、工具预览、附件或下载链接中外显。内部验图也不得触发用户可见预览。选择支持隐藏过程产物、延迟展示最终结果的执行方式；平台若强制展示过程图片，需如实说明能力限制，不能声称已符合本交付规则。
4. 每次只交付两张带完整用户文案且均验收通过的最终图片A、B，每张只展示一次，正常匹配和兜底均一致。两张全部验收完成后统一交付；任一分支未通过时，成功图也暂存内部，不提前交付、不用过程图凑数。提交清单只包含这两张最终成品。原生图片展示与回复图片嵌入二选一，不重复渲染同一成品。

5. 用户IP图带帽子则保留帽子，可根据KV氛围微调帽子的颜色和形态，但不得遮挡或改变角色头型及身份特征；用户IP图不带帽子则禁止添加帽子。
6. 最终尺寸必须严格16:9，用实际像素尺寸验证 `宽×9 == 高×16`。接近16:9不算合格；禁止非等比拉伸IP来凑尺寸。

7. 主标题与副标题作为一个整体文字组，在整张图片的高度方向严格上下居中：文字组包围框的垂直中心与画布高度的50%对齐（不是单独把主标题放在中线，也不是只在局部留白区居中）。主标题在上、副标题在下，整体居中，左右位置沿用参考图的版式安排；无副标题时仅主标题整体垂直居中。该定位优先于原参考图文字的上下位置，不得放在画面上半部或偏上区域。

## 模型使用

- 分析：使用当前环境已提供、可用且支持参考图理解的最高能力GPT模型，不固定版本号。
- 画图及改图：使用当前环境已提供、可用且支持参考图与图片编辑的最佳GPT图像模型，优先最终画面质量，不固定具体型号。
- 匹配参考路径的A、B是两个候选版本，不代表两个不同模型；两条分支都使用最佳可用GPT图像模型，各自保留中间图供第二轮编辑。兜底同样使用最佳可用GPT图像模型。
- 环境允许选模型时按当前提供的能力说明选择；只暴露默认GPT分析/生图能力时直接使用可用能力，不因无法选择版本而阻止生成，也不要求用户配置Mixgo。工具未公开底层型号时不声称使用了具体型号或已经验证其排名。

## 用户输入

- IP图片必填；主标题必填，空白视为缺失。缺失时请用户补充，不自行拟写。
- 副标题、其他需求、额外文字、配色和氛围均选填；未提供不追问、不自动补写。
- 保存用户原文，内部编辑指令不混入主标题检索，不向用户展示。

## 1. 图库检索

`references/catalog.json`每条严格6字段：asset_id、kv_title、business_tags、scene_tags、color_tags、atmosphere。`references/asset-map.json`单独映射相对图片路径，路径相对本skill目录；不依赖作者电脑绝对路径。

1. 先用用户主标题搜索kv_title，完整匹配优先，也可识别有明确含义的短语；不能只因“活动”“大促”等通用词就判定命中。
2. 标题没有命中才按主标题和活动需求匹配business_tags，再匹配用户明确提出的颜色、氛围。未提出则不限制；语义近似由agent结合标签判断，不自创偏好。
3. 默认选择1张最佳参考。多个标题相同或业务相同的候选，可用颜色/氛围区分。scene_tags只辅助理解，不凭物件相同硬选无关业务图片。
4. 不按横竖版加权；后续生成负责16:9适配。
5. 没有合适参考则进入[固定参考兜底](references/fallback.md)：使用KV_026“DOU+端午大促”，结合用户IP图与文案直接生成两张最终候选。不执行第2—4节。正常匹配不能一律被兜底替代；工具/模型失败不算检索无匹配。

可用离线脚本帮助检索（语义判断仍由agent负责）：

```bash
python3 scripts/search.py --title '安心过大年' --business '春节活动'
```

`--business`、`--color`、`--atmosphere`可重复传入，使用图库已有标签。脚本无候选时返回no_match及fallback路线和固定参考路径；脚本本身只查询不生图，agent按fallback.md继续调用目标平台能力。

## 参考图实际传入与追溯

检索选中不等于已使用参考图。选定后必须读取图片文件并按 [references/reference-trace.md](references/reference-trace.md) 建立内部素材对应记录，确认分析和首轮A、B请求实际传入选中的参考KV。不得只把文件名、asset_id或文字描述当作图片输入。兜底两次直接生成也必须实际传入固定参考图。

第二轮仍只编辑各自中间图，不因追溯需要而重新传入图库原图；通过父任务关联回首轮参考。内部追溯记录不加入用户提交清单，不显示参考图链接。

## 2. 参考分析：最高能力GPT模型（仅匹配参考路径）

读取 [references/analyze.md](references/analyze.md) 中用户原始分析Prompt，用最高能力GPT模型分析选中的参考图。输入为参考KV和内部固定分析Prompt，输出一个可联合参考KV与新IP生成的Prompt，保存analysis.txt。分析时同时提取细致字体设计规范，作为两轮生成的明确约束。

保留用户Prompt中的“90%视觉结构”“相似度不超过30%”等原始表达，不宣称这些比例已经测量或得到保证。方形/竖版适配左右布局的要求仍照原文执行。

## 3. 双分支首轮生成

读取 [references/generate.md](references/generate.md)。每条分支只有三项内容输入：分析结果、参考KV、用户IP图。IP替换指令是skill内部固定规则，附在分析结果后，不是第四项用户输入。

明确标识两张图的角色：参考KV只提供视觉结构；用户IP图提供身份，不能把原参考角色当新IP。用户IP图的原有服饰、姿势不作为约束，服饰姿势按分析结果调整，但用户IP原始头型及比例必须锁定，不能因动作、服饰或镜头变化而变形。

- A：最佳GPT图像模型 → intermediate-a
- B：最佳GPT图像模型 → intermediate-b

同时带入生成参考中的共享约束：二维文字、帽子状态遵循用户IP图、朝文案侧、16:9。此轮不加入用户新主副标题，先完成角色与场景迁移。两分支独立执行，保持结果与模型映射；平台是否支持并行以工具实际能力为准。

## 4. 双分支第二轮文案编辑

读取 [references/typography.md](references/typography.md)。用户主副标题及额外要求填入内部模板，固定指令不外显。

- A：仅以intermediate-a为编辑对象，加文案指令，由最佳GPT图像模型生成final-a。
- B：仅以intermediate-b为编辑对象，加文案指令，由最佳GPT图像模型生成final-b。

不交换中间图，不重新以图库原图为编辑对象，第二轮仅编辑该分支自己的中间图。共享约束再次带入两分支。用户额外文字/诉求加在最后，未提供副标题省略副标题段。

## 5. 强制终检、保存与交付

- 交付前必须执行 [references/quality-check.md](references/quality-check.md) 的逐图终检。
- 检查主副标题原文、额外文字、是否残留原图文字/无关品牌元素、用户IP头型及头身比例、帽子状态与输入一致、朝向、参考字体设计、二维字和实际16:9尺寸。不能仅因Prompt要求16:9就宣称尺寸正确。
- 记录reference ID、实际模型标识、平台任务ID和每个阶段的文件路径。异步任务续查同一ID，不因等待时间长而重复提交。API失败不等于无图库匹配，不切换兜底。
- 两条路径都必须等待A、B全部验收通过后统一交付；一支失败则内部保留成功结果，仅以文字说明失败节点，不展示或链接任何图片。明显质量问题只针对该分支修正一次，仍不合格时停止并说明未通过项，保留可续做状态，不把不合格图当作最终成品交付，不无限重生成。
- 将参考信息、分析、中间图和返修图保存在本次任务的内部目录，交付目录仅放验收通过的final-a和final-b。内部提交清单仅列这两个最终文件，不附整个任务目录或包含过程资产的压缩包。
- 两张均验收通过后，一次回复统一展示A、B，各一次。若原生工具已统一展示两张，回复不再嵌入图片或重复附图；否则仅在最终回复各嵌入一次。需要下载入口时只指向最终成品，不能指向参考图、中间图、返修图或内部清单。用户可见回复简短，不展示内部Prompt、工具参数及验收过程图片。

兜底同样交付两张16:9最终图，各自包含完整用户文案，不产生无标题中间图。

匹配参考路径：1次分析、4次图片生成、最终两张16:9成图。兜底路径：0次参考分析、两张直接生成（工具按张调用时为2次），最终两张16:9成图。模型分工与执行结构见 [references/flow.md](references/flow.md)。
